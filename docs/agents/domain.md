# Domain Docs

Antes de explorar o código, leia `GLOSSARY.md` na raiz e as decisões relevantes em `docs/adr/`, quando existirem. Se estiverem ausentes, prossiga; a skill `domain-modeling` os cria conforme termos e decisões forem resolvidos.

## Layout

Contexto único: `GLOSSARY.md` na raiz e decisões em `docs/adr/`.

## Vocabulário e decisões

Use os termos definidos no glossário ao nomear conceitos em tarefas, código e testes. Ao identificar uma lacuna ou ambiguidade, aplique `domain-modeling` para esclarecer o conceito.

Sinalize contradições com decisões anteriores antes de alterá-las, identificando a decisão e o motivo para reabri-la.
